## Success State (as of this session)

### Root cause finally found
The persistent "FSR shader compile error" (`ERROR: 0:35: 'max' : no matching overloaded function found` + `cannot convert from 'const mediump float' to 'mediump 3-component vector of float'`) was **NOT in FSRSuperEffect at all**.

**Root cause: `DetailBoostEffect.kt:109` used a 3-argument `max()`** which GLSL ES 2.0 does NOT support (only 2 args):

```glsl
vec3 maxRGB3x3 = max(max(nw, ne), max(sw, se), max(max(n, s), min(w, e)));  // BUG: 3-arg max + min(w,e) typo
```
Fixed to:
```glsl
vec3 maxRGB3x3 = max(max(max(nw, ne), max(sw, se)), max(max(n, s), max(w, e)));  // 2-arg max, max(w,e) correct
```

`DetailBoostEffect` sits EARLY in the pipeline (after LightBoost/FSR, before ColorBoost). When detail_boost was enabled, it crashed the whole video processing before `FSRSuperEffect` ever compiled. Every previous "FSR failed" test that had detail_boost ON was actually crashing at DetailBoost. This masked the true state of the FSR shaders.

### FSR consolidation now COMPLETE and WORKING
- `FSRSuperEffect.kt` = single combined FSR (EASU directional upscale + integrated RCAS sharpening + tone/chroma refinement) in ONE pass
- Uses `uTexelSize` uniform (NOT `textureSize` — this GLES 2.0 compiler rejects it)
- Uses only 2-argument `max()`/`min()`
- `drawFrame` sets `uSharpness` from `KEY_FSR_SHARPNESS` (default 60) plus `uTexelSize`
- **Verified A/B**: OFF vs FSR → ABS DIFF mean=0.768, max=58 → FSR genuinely sharpens (not passthrough); no GL errors

### Pipeline order (ExoPlayerActivity.kt)
`LowBitrateBoost → upscaler(MODE_FSR→FSRSuperEffect) → DetailBoost → LightBoost → ColorBoost`

### Lesson learned for future shader work
When a GLSL compile error appears at a CONSISTENT line number (0:35) across unrelated shader edits, suspect a DIFFERENT effect in the pipeline is crashing first, not the shader you're editing. Always check `logcat` for the actual `Program.<init>(SomeEffect.kt:NN)` class in the stack trace, not just the error message.
